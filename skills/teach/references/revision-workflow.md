# Systemic Course Revision

Classify feedback before editing:

- **Expression:** wording, layout, pacing, or local explanation; revise the page and related quick reference if needed.
- **Evidence/example:** recheck source and external evidence, then revise every page that repeats the claim.
- **Lesson boundary:** re-evaluate prerequisites, neighboring lessons, exercises, and plan ordering.
- **Module model:** rescan the relevant code and call paths; redraw architecture/module/sequence diagrams before rewriting prose.
- **Mission or track:** reconfirm `MISSION.md`, rerun only the diagnostic parts made stale, and submit a revised `COURSE-PLAN.md` for approval.

Before a non-local revision, give the user a concise impact analysis containing:

1. what the feedback reveals;
2. which assumptions, evidence, and diagrams need reinspection;
3. affected lessons and reference pages;
4. proposed split, merge, reorder, or track changes;
5. what remains valid.

For regenerated or supplemented content, work from this macro view. Update the architecture diagrams first when the underlying model changes, then propagate the new model through lessons, references, quizzes, self-tests, navigation, and status. Re-run HTML and citation verification after the changes.
