# 初始化项目协作规范

为当前项目建立：

- 根目录 `AGENTS.md`：长期工作规则、架构约束、文件地图及文档组织。
- 根目录 `_session_handoff.md`：当前状态、待办及当前 ISO 周工作记录。

先收集事实，生成完整审核稿，再根据用户确认写入目标文件。
最终回复保持在 500 字以内；交付物写入文件，仅返回文件路径及每个文件的一行描述。
若使用了 index 工具，同时列出文件对应的 index label；未使用时不编造标签。

## 1. 探索仓库

遵守当前生效的 Agent 指令，优先读取已有项目约定。

检查以下信息；不存在的项目跳过：

- 仓库根目录、Git 状态、远程仓库地址；非 Git 项目记录为不适用。
- `AGENTS.md`、`CLAUDE.md` 及相关子目录指令。
- `_session_handoff.md`、`handoff.md` 等已有交接文件。
- README、文档入口、架构文档、ADR 和交接归档。
- 包管理清单、锁文件、运行时版本及 workspace 配置。
- Dockerfile、Compose 文件、环境变量示例。
- CI 配置、开发脚本、测试及构建配置。
- 主要目录、应用入口、中间件、日志、数据访问及核心模块。
- 已配置的工作时区、本地源码参考库和工具偏好。

仓库已有 `.codegraph/` 时，先用 CodeGraph 理解和定位代码。
没有索引时，直接使用常规工具，不自行索引。

只探索生成文档需要的内容，不开展全仓库审计。
不安装依赖、不启动服务、不修改应用代码。
远程地址中若含凭据，输出和文档中必须脱敏。

区分已确认事实、待确认事项和不适用事项。
从配置读取命令不等于实际执行验证。

## 2. 确定输出和兼容方式

默认目标文件为 `AGENTS.md` 和 `_session_handoff.md`。

- 目标文件不存在：生成完整草稿。
- 目标文件已存在：原位补全，保留有效规则和用户内容。
- 存在 `CLAUDE.md`：读取并保持一致，不自动删除、迁移或重写它；
  若存在冲突，在草稿中列出具体处理建议。
- 存在其他名称的交接文件：提出沿用或迁移建议，展示迁移范围，
  避免维护两份重复状态。用户选择沿用时，同步替换模板中的交接文件引用。
- 已有文档布局：沿用实际路径，在 AGENTS.md 中说明分类和入口。
- 重复运行时更新现有章节，不追加重复章节或重复初始化记录。

不因发现某个工具而自动引入它的工作流。
任务跟踪、triage 标签及多上下文布局只在项目已采用或用户要求时记录。

## 3. 展示发现并补齐关键信息

简要说明项目类型、技术栈、运行方式、主要架构、已有文档和拟修改范围。
已能从仓库确定的信息不重复询问。
需要用户选择时给出推荐方案及理由。
非关键缺口在草稿中标记「待确认」，继续生成其余内容。
归档前必须确定工作时区；若项目和会话均未提供，则询问用户。

## 4. 生成可审核草稿

读取两个模板：

- [AGENTS.md 模板](assets/AGENTS.md.template)
- [交接模板](assets/_session_handoff.md.template)

按实际项目填充：

- 用真实路径、机制和命令替换 `{{...}}` 占位符。
- 删除不适用的示例行，必要章节写明「不适用」。
- 未知事项写「待确认」，不得编造命令、路径或验证结果。
- 架构图只描述当前实现。
- 文件索引只引用存在的文件或明确标注的拟新增文件。
- 保留输出限制、中文沟通、后端 logger、提交前交接更新、
  ISO 周归档和文档组织规则。
- 将长期约束放入 AGENTS.md，将阶段状态放入交接文件。
- 删除模板填写提示和示例注释，保留 Agent 实际需要执行的规则。

将完整草稿写到独立的临时审核目录，不覆盖目标文件；沿用已有审核目录时
避免覆盖用户修改的草稿。已有文件另附修改范围、规则冲突及历史内容处理说明。
在回复中仅提供审核文件路径及一行描述，不展开全文。

用户只要求草稿时，到此结束。
首次写入目标文件前取得对具体草稿的确认；已有确认且范围未变时不重复询问。

## 5. 写入确认后的内容

只写入已确认范围。默认创建或更新两个根目录文件。
如果需要新增 `docs/README.md` 等辅助文件，先在草稿阶段提供内容并纳入确认范围。

不预创建空文档目录。
首次实际归档时再创建 `docs/handoff/`、周文件及归档索引。

已有交接条目需要归档时，严格执行 AGENTS.md 中的归档规则：
先纯搬移并校验，再更新当前状态，不改写历史条目。
同日条目保留已有相对顺序；未来日期或不合法日期保留并报告，等待纠正。

保留当前仓库其他未提交改动。不自动 commit 或 push。

## 6. 检查结果

- 两个目标文件存在，名称和相互引用一致。
- 无未替换的模板占位符；未知事项已明确标记。
- 已有有效规则和历史条目未丢失。
- 路径、命令及架构描述有实际依据。
- 文档布局与已有目录一致。
- 当前焦点仅保留当前 ISO 周日期条目；日期异常单独报告，不静默移除。
- 如发生归档，非空行多重集校验通过。
- 归档索引与根目录历史导航一致。
- 重复运行不会产生重复章节或重复历史记录。
- 最终 diff 仅包含已确认的文档变更。

文档初始化无需运行应用测试。
如未实际运行开发命令，在文档中明确标注未验证。

## 7. 交付

仅返回创建或更新的文件路径及一行描述，总计少于 500 字。
若使用了 index 工具，附对应 index label。
将验证结果和待确认信息写入审核目录中的交付说明，并返回其路径。
说明中记录：Agent 先读 AGENTS.md，再读交接文件；这些文件可直接维护，
项目约定需要重新梳理时再运行本 skill。
